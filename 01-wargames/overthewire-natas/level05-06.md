# Level 5 → 6

## 1. 목표 (Objective)
페이지 내에서 비밀번호 찾기

## 2. 사용 명령어 (Commands)
`없음`

## 3. 풀이 과정 (Procedure)
1. 페이지 내용은 접근 거부, 로그인 하지 않았다고 나옴
    - 화면 어디에도 로그인을 할 수 있는 곳이 보이지 않음
2. 정보가 쿠키에 담긴 것인지 궁금해 개발자도구를 열어 `Storage` 탭으로 이동
    - `loggedin`이 존재하며 값은 0으로 존재
3. `loggedin` 값을 1로 변경
4. 새로고침 진행 → 접근 허용 및 계정 정보 확인

## 4. 원리 (Theory)
- `cookies`
  - 사용자가 방문한 웹사이트의 웹 서버가 생성한 텍스트 파일로 사용자의 웹 브라우저에 저장하고 서버 요청에 필요한 경우 같이 전달
  - 해당 값 또한 변조가 가능
- `loggedin`
  - 서버가 해당 쿠키의 값만으로 로그인 여부를 확인한다고 판단
  - Guessing attack 기법에 따라 0은 `boolean` 타입의 `false`를 나타낸다고 판단 및 가정 진행
  - 따라서 `true`를 의미하는 1로 변경하여, 로그인 상태임을 전달
- Guessing attack
  - 공격자가 비밀번호, 세션 ID, 토큰처럼 모르는 값을 흔히 사용되는 값으로 추측해서 대입하는 공격
  - 이번 레벨에서는 비밀 값이 아니라 `loggedin` 값의 의미(0=false, 1=true)를 추측해서 적용함

# 보고서
> 워게임의 비밀번호가 노출된 것이 아닌, admin 계정으로 로그인된 것으로 산정
> 데이터 변경 기능이 확인되지 않아 무결성 영향은 낮게 산정

## 1. 취약점 요약
| 항목 | 내용 |
|------|------|
| 취약점명 | 쿠키 값 변조를 통한 인증 우회 |
| 분류 | CWE-565 (Reliance on Cookies without Validation and Integrity Checking) |
| 대상 | natas5 웹 페이지 |
| 위험도 | 8.2 (High) |
| 벡터 | `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N` |

## 2. 취약점 설명
- 서버가 클라이언트 쿠키의 `loggedin` 값만으로 로그인 여부를 판단하며, 별도의 검증이나 무결성 보호가 없음
- 쿠키는 클라이언트가 임의로 변경할 수 있는 값이므로 개발자도구로 값을 변조하면 인증 없이 로그인 상태로 인식시킬 수 있음

## 3. 재현 절차
1. 대상 페이지 접속 → 접근 거부(로그인하지 않음) 메시지 확인
2. 개발자도구 `Storage` 탭에서 쿠키의 `loggedin` 값(0) 확인
3. `loggedin` 값을 1로 변경
4. 페이지 새로고침 → 로그인 상태로 인식되어 접근 허용 및 계정 정보 확인

## 4. 영향 (Impact)
- 인증 우회로 admin 계정으로 로그인된 것과 같은 접근이 가능하여 정보 열람 가능, 변경 기능은 확인되지 않아 무결성 영향은 낮게 산정
- 브라우저 개발자도구만으로 공격이 가능하며 별도의 고급 기법이 필요하지 않아 악용 난이도가 낮음

## 5. 대응 방안 (Remediation)
- 인증 상태를 쿠키 값에 직접 저장하지 않고 서버 측 세션으로 관리
- 세션 ID는 추측이 불가능한 난수로 발급하고 서버에서 유효성 검증
- 쿠키를 사용해야 하는 경우 서명 등 무결성 검증 적용
- 쿠키에 `HttpOnly`, `Secure`, `SameSite` 속성 적용
