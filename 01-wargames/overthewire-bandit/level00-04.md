# Level 0 → 1

## 1. 목표 (Objective)
`ssh`로 접속하여 로그인 후 홈 디렉토리에 있는 `readme`를 읽어 bandit1의 비밀번호 얻기

## 2. 사용 명령어 (Commands)
`ssh`, `ls`, `cat`

## 3. 풀이 과정 (Procedure)
1. `ssh -p 2220 bandit0@bandit.labs.overthewire.org`
2. 비밀번호 입력
3. `ls`
4. `cat readme`

## 4. 원리 (Theory)
- SSH
  - SSH는 암호화된 채널로 원격 서버에 접속하는 프로토콜
  - `-p {port}`은 기본 포트(22) 대신 다른 포트로 접속하는 옵션
  - 접속 후에는 해당 계정의 홈 디렉토리에서 시작
- 이외
  - `ls`
    - 파일의 목록을 볼 수 있는 명령어
  - `cat`
    - 파일의 내용을 보여주는 명령어

# Level 1 → 2

## 1. 목표 (Objective)
홈 디렉토리에 있는 `-` 파일을 읽어 bandit2의 비밀번호 얻기

## 2. 사용 명령어 (Commands)
`ls`, `cat`

## 3. 풀이 과정 (Procedure)
1. `ls` 명령어로 파일 확인
2. `cat -` 실행 → 입력 대기 상태로 멈춤
3. `cat ./-` 실행

## 4. 원리 (Theory)
- `cat`
  - 대기 상태로 멈춘 이유
    - 리눅스에서는 `-`이 표준 입력(stdin)을 뜻하는 특수한 예약어이기 때문에 입력값을 기다리는 상태가 됨.
    - 따라서 `-`로 시작하거나 `-`만 존재하는 경우 두 가지의 방법이 있음.
      1. `cat ./-` : `./`를 붙여 현재 디렉토리라고 명시하기
      2. `cat -- -` : `-`로 시작하는 경우는 `--`를 사용해 옵션이 끝남을 알려줄 수 있음. 이 경우 `-`라는 이름의 파일은 읽을 수 없었음. `--` 뒤의 `-`도 다시 stdin 예약어로 해석한 것으로 보임.

# Level 2 → 3

## 1. 목표 (Objective)
홈 디렉토리에 있는 파일을 읽어 bandit3의 비밀번호 얻기

## 2. 사용 명령어 (Commands)
`ls`, `cat`

## 3. 풀이 과정 (Procedure)
1. `ls` 명령어로 파일 확인
2. `cat --spaces in this filename--` 실행 → error 발생 : unexpected argument
3. `cat ./--*` 실행

## 4. 원리 (Theory)
- `cat`
  - 에러가 발생한 이유
    - 쉘이 공백을 기준으로 인자를 나누기 때문에 `--spaces`, `in`, `this`, `filename--` 네 개의 인자로 전달됨
    - 그중 `--spaces`가 `--`로 시작해서 파일명이 아니라 존재하지 않는 옵션으로 해석됨
  - 해결 방법 : `cat ./--*`
    - `*`는 와일드카드로, 쉘이 `--`로 시작하는 파일명으로 바꿔서 `cat`에 전달함. 공백이 있어도 하나의 인자로 전달됨
    - `./`를 앞에 붙여 옵션이 아니라 경로로 인식되게 함

# Level 3 → 4

## 1. 목표 (Objective)
inhere 디렉토리의 숨겨진 파일에서 bandit4의 비밀번호 얻기

## 2. 사용 명령어 (Commands)
`ls`, `cat`

## 3. 풀이 과정 (Procedure)
1. `ls` 명령어로 홈 디렉토리 파일 확인
2. `ls ./inhere` 명령어로 inhere 내부 파일 확인
3. `ls -a ./inhere` 명령어로 숨김 파일 확인
4. `cat inhere/{숨김 파일}` 실행

## 4. 원리 (Theory)
- 숨김 파일
  - 리눅스에서 숨김 파일은 `.`로 시작하는 파일명으로 설정 가능
- `ls`
  - `-a` 옵션 : 숨김 파일을 확인 가능
  - `-l` 옵션 : 리스트 형식으로 확인이 가능하며, 각 파일의 권한, 수정 날짜, 용량 확인 가능
  - `-al`과 같이 여러 개를 같이 쓸 수 있음.
